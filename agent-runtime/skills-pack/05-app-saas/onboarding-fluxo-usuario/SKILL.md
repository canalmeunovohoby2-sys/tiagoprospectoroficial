# Onboarding e Ativação de Usuários

## Princípio central
O objetivo do onboarding não é "cadastrar o usuário", é levá-lo o mais rápido possível ao primeiro valor real do produto (o "momento aha"). Cada campo/etapa extra antes disso reduz ativação.

## Estrutura recomendada
1. Cadastro mínimo (nome, e-mail/telefone, senha ou login social) — dados adicionais podem ser coletados progressivamente depois, não tudo de uma vez.
2. Perguntas de personalização curtas (2-4 no máximo) para adaptar a experiência inicial ao caso de uso do usuário (ex: "qual seu segmento de negócio?").
3. Checklist de setup guiado (3-5 passos) mostrando progresso visual, levando o usuário a configurar o mínimo necessário para ver valor (ex: "conectar sua primeira conta", "criar seu primeiro projeto").
4. Tour contextual (tooltips pontuais na primeira vez que uma funcionalidade aparece) em vez de um tour genérico de 10 telas no início — ninguém lembra de tour longo antes de usar o produto.
5. E-mails de ativação: sequência curta reforçando o próximo passo caso o usuário não complete o setup em X dias.

## Métricas a acompanhar
- Taxa de conclusão de cadastro, taxa de conclusão do setup inicial, tempo até o "momento aha", e retenção em D1/D7/D30 — usar esses dados para identificar onde o funil de ativação perde usuários.

## Checklist
- [ ] O cadastro inicial pede o mínimo indispensável?
- [ ] Existe um checklist/progresso visual guiando até o primeiro valor real?
- [ ] O tour é contextual, não uma sequência genérica de telas no início?
